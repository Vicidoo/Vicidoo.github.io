OneBot 的 WebSocket 一直报 1006：两个配置文件同名项互相覆盖

2026-10-30白幻918 字#OneBot#折腾#白幻
收录于合集「白幻的手记」
目录

    现象

    给 QQ 机器人换协议端之后，HTTP 接口正常：get_login_info 能返回账号和昵称，说明登录、端口、鉴权都没问题。

    WebSocket 一直连不上，客户端反复断开，服务端日志只有一行 WebSocket 1006，没有错误码，也没有原因。

    1006 表示连接异常关闭，且没有收到关闭帧。它不携带具体原因，只能说明连接是被对方直接断开的。

    排查

    先确认网络：端口通、握手能完成，走本地回环，不涉及 TLS。

    再确认鉴权：HTTP 用 Authorization: Bearer，WebSocket 用 URL query 参数，是两个独立入口，各自的 token 分开配置。

    问题在配置值上：onebot.json 里 wsServers[].accessToken 和 httpServers[].accessToken 是两个字段，第一次只改了前者。

    改完仍然 1006。检查数据目录时发现还有第二个文件 onebot_<uin>.json，同目录、同结构，文件名带账号。它的加载顺序在主配置之后，会覆盖主配置里的同名项。

    也就是说，改 onebot.json 一直没生效。

    修复

    两个文件都改成一致的值：

    "wsServers": [{ "accessToken": "<同一个值>" }],
"httpServers": [{ "accessToken": "<同一个值>" }]

    改之前备份两个文件，改完重启协议端容器。

    验证

    • WebSocket 不再返回 1006，客户端连上后能收到事件
    • HTTP 接口鉴权正常
    • 机器人私聊、群聊收发都正常

    遗留问题

    重启容器会掉登录。 协议端不是无状态服务，进程重启后要重新完成一次登录确认，这一步没法自动化。改配置本身很快，麻烦的是后面要盯着登录状态。

    覆盖文件没有提示。 配置项写在两个文件里，缺一个不报错，只是静默不生效。以后遇到「改了没反应」，先 ls 一遍配置目录，看有没有带账号后缀的副本。

    1006 不带信息。 不用在这个错误码上找原因，直接查「连接是在什么时间、被哪一端断掉的」。

    整件事的结论：不是网络问题，也不是鉴权方式问题，是两个文件里的同名配置项，后加载的那个覆盖了前面的。
